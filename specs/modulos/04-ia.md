# 04 · Servicio de IA (`ai`)

**Estado:** Borrador v0.1 · **Fase:** F0 (la base) + F2 (primer uso: MENU-07) · **Depende de:** `00-plataforma.md`

## 1. Objetivo

Dejar una **base única para usar modelos de IA** (Claude por defecto, intercambiable por otros proveedores) que cualquier módulo pueda usar para gestiones de los locales, sin que nadie llame a un proveedor directamente.

Debe servir el primer caso real (traducción de la carta, MENU-07) y dejar preparados los siguientes sin rehacer nada: medir el coste por cliente, poner límites, cambiar de modelo o proveedor por configuración y proteger los datos de los comensales.

**No es un módulo que se venda en el MVP.** Es una capacidad interna de la plataforma. Si más adelante se vende como extra, se añadirá a `ModuleKey` (ver Preguntas abiertas).

## 2. Alcance MVP

**Incluye:** conexión con proveedores con un adaptador común, tareas tipadas y versionadas, salida estructurada validada con Zod, registro de uso y coste por tenant, presupuestos y límites, trabajos en segundo plano, revisión humana de todo lo que se publica, reglas de privacidad, proveedor simulado para tests y panel de uso en el superadmin.

**Fuera de alcance MVP:** chat o asistente para comensales, agentes que actúan solos con herramientas sobre los datos del local, búsqueda semántica (embeddings/RAG), voz, imágenes generadas y ajuste fino de modelos. El diseño no debe impedirlos, pero no se construyen.

## 3. Arquitectura

```
packages/ai/                      # Conexión con proveedores. Sin Prisma ni Next.
  src/
    client.ts                     # runTask(): punto de entrada único
    providers/
      registry.ts                 # "anthropic:claude-haiku-5-5" → adaptador
      anthropic.ts                # proveedor por defecto
      openai.ts                   # opcional, mismo contrato
      mock.ts                     # respuestas fijas para tests (AI-08)
    models.ts                     # niveles fast / standard / advanced → modelo (desde env)
    pricing.ts                    # precio por millón de tokens de cada modelo
    errors.ts                     # errores tipados: AI_TIMEOUT, AI_INVALID_OUTPUT…
apps/platform/src/modules/ai/     # Bounded context de la plataforma
  domain/                         # definición de tareas, reglas de presupuesto
  application/                    # runAiTask, enqueueAiJob, getUsage
  infra/                          # repositorios AiUsage, AiJob, AiSettings
  tasks/                          # una carpeta por tarea, versionada
    menu-translate/
      v1.ts                       # prompt + schemas de entrada y salida
      evals.json                  # casos de prueba con respuesta esperada
```

**Librería:** [Vercel AI SDK](https://ai-sdk.dev) (`ai` 7.x) con `@ai-sdk/anthropic` como proveedor por defecto. Da una interfaz común a varios proveedores (Anthropic, OpenAI, Google, Mistral…), salida estructurada con Zod y streaming. Cambiar de proveedor es cambiar una variable de entorno y añadir su paquete, no reescribir código.

**Elección de modelo por nivel, nunca en el código:**

| Nivel | Para qué | Valor inicial (`.env`) |
|---|---|---|
| `fast` | Tareas cortas y repetitivas: traducir un plato, clasificar | `AI_MODEL_FAST=anthropic:claude-haiku-5-5` |
| `standard` | Redactar textos, resumir, revisar | `AI_MODEL_STANDARD=anthropic:claude-sonnet-5-5` |
| `advanced` | Casos complejos, solo si una tarea lo justifica | `AI_MODEL_ADVANCED=anthropic:claude-opus-5-5` |

Opcional: `AI_FALLBACK_STANDARD=openai:…` para usar otro proveedor si el principal falla (AI-01).

### Contrato de una tarea (referencia)

```ts
// packages/ai — tipos (boceto; los nombres finales pueden variar)
export interface AiTask<I, O> {
  id: string;                 // "menu.translate"
  version: number;            // sube si cambia el prompt o el schema
  tier: 'fast' | 'standard' | 'advanced';
  input: z.ZodType<I>;
  output: z.ZodType<O>;       // la respuesta del modelo se valida siempre
  personalData: 'none' | 'minimal'; // AI-07: declarado en cada tarea
  maxOutputTokens: number;
  buildPrompt(input: I): { system: string; prompt: string };
}

export type AiResult<O> =
  | { ok: true; data: O; usage: { inputTokens: number; outputTokens: number; costMicros: number; model: string } }
  | { ok: false; code: 'AI_DISABLED' | 'AI_BUDGET_EXCEEDED' | 'AI_RATE_LIMITED' | 'AI_TIMEOUT' | 'AI_PROVIDER_ERROR' | 'AI_INVALID_OUTPUT' };

// apps/platform/src/modules/ai/application
runAiTask(tenantId, task, input): Promise<AiResult<O>>      // síncrono, para tareas cortas
enqueueAiJob(tenantId, task, input, { idempotencyKey }): Promise<{ jobId: string }> // tareas largas
```

## 4. Modelo de datos

```prisma
model AiSettings {
  tenantId            String  @id
  enabled             Boolean @default(true)
  monthlyBudgetMicros Int     @default(2000000)   // 2 € al mes por defecto; micro-euros (1 € = 1.000.000)
  disabledTasks       String[]                     // ids de tarea desactivados para este tenant
}

model AiUsage {
  id           String   @id @default(cuid())
  tenantId     String?                             // null = uso interno o del superadmin
  taskId       String                              // "menu.translate"
  taskVersion  Int
  provider     String                              // "anthropic"
  model        String
  inputTokens  Int
  outputTokens Int
  costMicros   Int                                 // coste estimado en micro-euros con la tabla de pricing.ts
  latencyMs    Int
  status       String                              // ok | invalid_output | timeout | provider_error
  jobId        String?
  createdAt    DateTime @default(now())
  @@index([tenantId, createdAt])
  @@index([taskId, createdAt])
}

model AiJob {
  id             String   @id @default(cuid())
  tenantId       String
  taskId         String
  taskVersion    Int
  idempotencyKey String
  input          Json
  output         Json?
  status         String   @default("PENDING")      // PENDING | RUNNING | DONE | FAILED
  attempts       Int      @default(0)
  error          String?
  createdAt      DateTime @default(now())
  finishedAt     DateTime?
  @@unique([tenantId, idempotencyKey])
  @@index([status, createdAt])
}
```

Por defecto **no se guarda el texto de los prompts ni de las respuestas** en `AiUsage`, solo metadatos (AI-07). El resultado útil se guarda donde lo usa el módulo (por ejemplo, `Translation` en la carta).

## 5. Historias de usuario

### AI-01 · Conectar con proveedores
- Toda llamada a un modelo pasa por `packages/ai`. Prohibido importar SDKs de proveedores fuera de ese paquete.
- El modelo de cada nivel y el proveedor de respaldo se leen de variables de entorno; sin clave configurada, `runAiTask` devuelve `AI_DISABLED` y la funcionalidad que lo usa se oculta, sin romper la página.
- Tiempo máximo por llamada configurable (30 s por defecto). Un reintento ante error temporal (429, 5xx) con espera; si vuelve a fallar y hay respaldo configurado, se prueba el respaldo una vez.
- Comprobación de estado en el superadmin: un botón "Probar conexión" por nivel.

### AI-02 · Tareas tipadas y versionadas
- Cada uso de IA es una tarea registrada en `modules/ai/tasks/`, con id, versión, nivel, schemas de entrada y salida y prompt. No hay prompts escritos sueltos en otros módulos.
- La salida se pide estructurada y se valida con su schema Zod. Si no valida, se reintenta una vez; si vuelve a fallar → `AI_INVALID_OUTPUT`, sin guardar nada.
- Cambiar un prompt o un schema obliga a subir la versión y a pasar sus evals (AI-08).

### AI-03 · Uso y coste por cliente
- Cada llamada crea un `AiUsage` con tokens, modelo, coste estimado y latencia, también si falla.
- `pricing.ts` guarda el precio por millón de tokens de cada modelo, en euros; se revisa cuando el proveedor cambie tarifas.
- El OWNER ve en su panel cuánto ha usado este mes frente a lo incluido (si se muestra; ver Preguntas abiertas).

### AI-04 · Presupuestos y límites
- Antes de cada llamada se comprueba: IA activada para el tenant, tarea no desactivada, gasto del mes por debajo de `monthlyBudgetMicros` y límite de ritmo (20 llamadas por minuto por tenant).
- Al superar el presupuesto → `AI_BUDGET_EXCEEDED`; la interfaz explica qué pasa y que se renueva el día 1.
- Tope global mensual de la plataforma (`AI_GLOBAL_BUDGET_EUR`): al alcanzar el 80 % se avisa al superadmin por la outbox; al 100 %, se cortan las tareas no esenciales.

### AI-05 · Trabajos en segundo plano
- Las tareas largas (traducir una carta entera) van por `enqueueAiJob`; un cron cada minuto procesa los `PENDING` (máximo 3 intentos, como la outbox).
- **Nunca** se llama a un modelo dentro de una transacción de base de datos ni desde el render de una página pública.
- `idempotencyKey` evita duplicar el trabajo si el usuario pulsa dos veces.
- El panel muestra el progreso ("Traduciendo 34 de 80 platos") y el resultado al terminar.

### AI-06 · Revisión humana
- Todo lo generado que vaya a verlo un comensal (traducciones, textos de la web, respuestas a reseñas) se guarda como **borrador** y no se publica hasta que el OWNER lo acepta. Así funciona ya MENU-07 (`DRAFT_AI` → `REVIEWED`).
- La IA **nunca** decide sola sobre alérgenos, precios ni reservas: puede sugerir o avisar, la decisión es siempre de una persona.

### AI-07 · Privacidad y datos
- Cada tarea declara `personalData`. Las tareas `none` no reciben nombres, teléfonos, emails ni notas de comensales; se comprueba en los tests.
- Las tareas `minimal` (por ejemplo, responder a una reseña pública) envían solo lo imprescindible y nunca datos de salud.
- Proveedores contratados en condiciones que excluyan entrenar con los datos enviados; se revisan y documentan antes de activar cada proveedor.
- Cada proveedor de IA activo figura como subencargado en el contrato de encargo de tratamiento (PLT-10).

### AI-08 · Pruebas y evaluación
- En tests, CI y previews se usa siempre el proveedor `mock`; ningún test llama a una API real.
- Cada tarea tiene un `evals.json` con 5–10 casos y la respuesta esperada (o criterios). `pnpm ai:eval <tarea>` los ejecuta contra el modelo real a mano, antes de subir una versión.

### AI-09 · Panel del superadmin
- Gasto por día, por tenant y por tarea; tasa de errores y latencia media.
- Activar o desactivar la IA por tenant y por tarea; cambiar su presupuesto, con motivo en `AuditLog`.

## 7. Tests clave

- AI-01: sin `ANTHROPIC_API_KEY`, la traducción de la carta no aparece y la página carga.
- AI-02: una respuesta que no cumple el schema se reintenta una vez y después devuelve `AI_INVALID_OUTPUT` sin guardar nada.
- AI-04: un tenant con el presupuesto agotado recibe `AI_BUDGET_EXCEEDED` y no se llama al proveedor.
- AI-05: dos `enqueueAiJob` con la misma `idempotencyKey` crean un solo trabajo.
- AI-07: el input enviado por una tarea `personalData: none` no contiene ningún dato de `Customer` (test con datos de semilla).
- Aislamiento: el OWNER del tenant A no ve el uso ni los trabajos del tenant B.
